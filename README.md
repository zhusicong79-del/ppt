# SmartX Content Studio Demo

企业案例与产品介绍的 HTML 内容工作台。使用 Node.js 22+，无第三方运行依赖。

```sh
npm start
# 默认端口 3000，PORT 可覆盖
npm test
```

## 演示账号

- `demo@smartx.com`：SmartX 演示组织
- `demo@partner.com`：合作伙伴演示组织
- 密码均为 `Demo2026!`

提供内容搜索与分类、模块自由拼接、标题/正文/版式编辑、页面拖动排序、复制/删除、预览、租户文稿保存、离线 HTML 导出。浏览器打印导出的 HTML 可生成 PDF。

服务端通过 HttpOnly 会话识别账号，按租户保存到忽略的 `.data/tenant-<id>.json`；前端不能指定其他租户。退出会销毁会话，会话过期时间 24 小时。演示账号属于同一租户时应共享内容空间。

Google Drive 文件和 CRM 客户均为明确标注的模拟数据。导入演示 PPT 会加入预设模块，**不解析真实 PPTX**。不需要公司账号、凭据或外部 API。

正式 Google Drive 接入需配置公司 Google OAuth 客户端、最小只读权限、允许的共享盘、服务端安全存储授权以及 PPTX 转换服务。CRM 接入需明确供应商、接口、授权及租户映射。上线前应替换演示账号为公司 SSO，使用持久化会话和数据库、HTTPS、安全审计及权限体系。当前文件存储、内存会话和公开演示密码仅用于 demo，不适合生产。

视觉配色参考 https://www.smartx.com/ 官网样式中的 #00122e、#0080ff、#009dff 与 #f2f5fa；文字标识与内容为演示重建，不代表正式品牌素材或客户案例。

验证：`npm test` 验证未登录拒绝、错误密码、登录、持久保存、两个租户隔离、输入校验、模拟接口及退出失效。浏览器冒烟验证登录、模块添加、编辑与保存后刷新、模拟 Drive 导入、CRM 关联、HTML 下载、预览和移动端渲染。

## 部署

提供 `Dockerfile` 和 `render.yaml`。Render Blueprint 可读取本仓库配置创建 Node Web Service；仓库需要先推送代码，并由拥有仓库访问权限的 Render 账号授权导入。没有部署平台授权时不能创建公网地址。

Render 免费服务上的本地文件不是持久存储：重启、重新部署时保存的演示可能丢失。需要长期保存时应改用持久磁盘或数据库。当前会话在内存中，服务重启后需重新登录。当前部署只适合使用演示数据，不要上传公司机密。

Docker 自托管示例：

```sh
docker build -t smartx-studio .
docker run -d --name smartx-studio -p 3000:3000 -v smartx-studio-data:/app/.data smartx-studio
```

公网部署应由托管平台或反向代理提供 HTTPS。

## 第二版：页面组装工作台

左侧为方案工作区（页面目录、画布、内容编辑），右侧为来源素材窗口。素材包含 3 份演示文件、11 张可浏览的 HTML 页面。可以跨文件拖拽单页到目录指定位置或画布、整份添加、拖动目录排序、直接编辑画布文字、撤销最近的编辑与组装操作。素材复制到方案后保留来源文件和页码，与素材库独立。

“文字生成页面”通过 `/api/generate` 将输入内容分段，并套用所选演示版式。**它是确定性文字整理与模板排版，不调用 AI、不编造内容，也尚未读取公司真实 PPT 母版。** Google Drive 管理来源可切换文件与浏览全部页面；刷新只重新读取演示素材，不执行真实外部同步。

真实 Drive 接入应支持公司 OAuth、共享盘及文件夹范围、分页全量索引、增量同步任务、PPTX 解析/预览转换、页级来源与权限继承。公司母版和实际演示文件需要通过受控导入获得；AI 模型需经公司授权后接入。平台注入的通用云凭据不应被当作公司 Google Drive 授权。

第二版验证包括跨素材拖拽、画布直接编辑、模板排版生成、保存刷新、排序与撤销、文件筛选和 HTML 导出。API 测试覆盖来源页码、生成输入校验及 HTTPS 同源写操作（适用于 Render TLS 终止后转发）。

## 第三版：基础设施拓扑与品牌视觉

工作区增加基础设施素材面板：服务器、交换机、存储、云平台、防火墙、业务终端与网络连线。选择“＋ 拓扑页”可建立空白拓扑，或选择“插入架构示例”建立演示架构。图标支持点击添加及拖入画布；设备支持指针拖动、标签编辑、复制和删除；连线模式下依次点击两个设备建立连线，再修改标签、直线/折线/虚线、箭头方向。删除设备会移除关联连线，操作支持撤销。

拓扑随页面保存，使用 `diagram.nodes` 和 `diagram.edges`，服务端验证设备类型、坐标范围、唯一 ID 与有效连线引用，继续使用登录账号的租户空间。每页最多 80 个设备和 200 条连线。导出的 HTML 内嵌拓扑 SVG 和品牌图片，离线打开不依赖官网。编辑模式的画布网格不显示在导出内容中。

视觉参考 SmartX 官网的深海军蓝、亮蓝、浅蓝与紫色立体图形、浅色导航与简洁版式。官网首页图形本地副本位于 `public/assets/smartx-brand.png`，来源为 https://cdn.smartx.com/inc/images/home/hero_smartx_sunmao_logo.png 。设备图标是为本 Demo 绘制的统一风格 SVG，**不是公司内部正式素材**；尚未导入公司原始图标或实际 PPT 母版。

第三版 API 测试覆盖拓扑持久化、跨租户隔离、悬空连线、重复 ID、非法类型和坐标的拒绝。浏览器验证覆盖设备添加与拖入、节点移动、连线属性、删除连线关联清理、撤销、保存刷新以及带内嵌图片的 HTML 导出。

## 第四版：真实公司模板与三种导出

两份内部主打 PPT 作为正式模板（30 页虚拟化、171 页超融合，含隐藏页）。原文件和 201 页预览只存在租户私有 `.data`，不会推送到代码仓库。支持导入原始 PPTX、使用原始页面新建与生成、套用版式、修改原始文本、更新渲染预览，并基于同一源模板导出 PDF、HTML 和 PPTX。

新增 Python/LibreOffice 转换组件与 Docker 服务配置；旧 Node Demo 仍保留。线上专用账号、模板导入、OAuth、持久化与字体说明见 [DEPLOYMENT.md](DEPLOYMENT.md)。Drive 文件夹链接已作为预设目标，真实授权及公司同步未完成；自动定时同步尚未实现。
